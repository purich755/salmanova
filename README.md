# Salmanova — авторские украшения Светланы Салмановой

Редизайн salmanova.ru (Tilda). С исходного сайта перенесено всё: три страницы, 523 товара каталога с ценами,
описаниями, остатками, скидками и 653 фото, 29 разделов магазина, доставка, форма заявки, три адреса,
соцсети, реквизиты. Тексты взяты с сайта без изменений.

## Запуск

```bash
node tools/serve.mjs 8517
```

Откройте http://localhost:8517. Сервер отдаёт чистые адреса `/about` и `/info`, как на исходном сайте.

## Публикация

Сайт публикуется на GitHub Pages: https://purich755.github.io/salmanova/. Каждый пуш в `main` запускает
`.github/workflows/pages.yml`: страницы пересобираются с префиксом `/salmanova` и выкладываются.
Vercel не подходит: `*.vercel.app` в России открывается не у всех, особенно через мобильный интернет.

Чтобы проверить сборку с префиксом локально:

```bash
BASE=/salmanova node tools/build-html.mjs && node tools/serve.mjs 8518 /salmanova
```

В Git Bash перед командой нужно добавить `MSYS_NO_PATHCONV=1`, иначе `/salmanova` превратится в путь Windows.
После проверки верните обычную сборку командой `node tools/build-html.mjs`.

Когда сайт переедет на домен salmanova.ru, префикс не нужен: страницы собираются без `BASE`.

## Что где

| Путь | Что это |
|---|---|
| `index.html`, `about.html`, `info.html`, `404.html` | готовые страницы (собираются скриптом, руками не править) |
| `src/pages`, `src/partials` | исходники страниц: шапка, подвал, карточка товара и заявка — общие |
| `css/style.css` | все стили |
| `js/` | каталог и фильтры (`catalog.js`), заявка (`cart.js`), анимации (`motion.js`), карта (`stores.js`), «стёкла» на странице «О Светлане» (`about.js`) |
| `data/catalog.json` | каталог для сайта |
| `assets/p` | фото товаров в WebP: `-s` — для карточек, `-l` — для крупного просмотра |
| `vendor/` | GSAP 3.15 (ScrollTrigger, SplitText) и Lenis — локально, без CDN |
| `raw/` | выгрузка с исходного сайта и оригиналы фото (430 МБ, в деплой не нужна) |
| `tools/` | сборка и самопроверка |

## Обновить каталог с Tilda

```bash
curl -s "https://store.tildaapi.com/api/getproductslist/?storepartuid=984380400551&recid=785176804&getparts=true&getoptions=true&slice=1&size=500" -o raw/products.json
curl -s "https://store.tildaapi.com/api/getproductslist/?storepartuid=984380400551&recid=785176804&getparts=true&getoptions=true&slice=2&size=500" -o raw/products2.json
node tools/parse.mjs
node tools/fetch-photos.mjs
node tools/build-assets.mjs
node tools/build-html.mjs
```

После правок в `src/` достаточно `node tools/build-html.mjs`.

## Что нужно решить с заказчиком

1. **Правила ухода за украшениями.** На исходной странице «Инфо» под этим заголовком стоит шаблонный текст Tilda
   про регистрацию на мероприятие. Переносить его не стал: в разделе сейчас предложение написать в мессенджер
   или на почту. Нужен настоящий текст от заказчика.
2. **Куда уходят заявки.** На Tilda форма отправлялась в её обработчик. Здесь заявка собирается в готовый текст,
   и покупатель отправляет его в WhatsApp, Telegram, Viber или на почту (первой кнопкой идёт мессенджер, выбранный
   в форме). Если нужен приём заявок на сервере (Telegram-бот, CRM, почта), укажите адрес в `ORDER_ENDPOINT`
   в `js/cart.js`: заявка уйдёт туда POST-запросом в JSON.
3. **Карты.** На исходном сайте все три карты стояли на координатах Нью-Йорка. Здесь координаты адресов
   взяты из OpenStreetMap. Стоит проверить точку в аэропорту Курумоч: сейчас она стоит в центре аэропорта.
4. **Instagram.** Ссылка перенесена как есть: на исходном сайте она есть у салона в Москве и Самаре.
5. У восьми товаров на Tilda пустое поле цены. У двух из них сумма была вписана в описание («18 000 ₽», «6980 ₽»),
   её перенёс в поле цены. Остальные шесть показаны как «Цена по запросу».
